# 智能体工作室

## 项目概况

智能体工作室是一个基于 Ollama 模型的多智能体协作系统，采用**管理控制单元+无限扩展执行单元**的架构设计，实现任务的自动拆解、角色定义、并行执行和结果汇总。系统遵循**任务规划→角色建模→多执行单元并行执行→结果汇总答复**的核心流程，结合指定 Ollama 模型做算力与效果的最优匹配，全程无思考模式、纯流程化执行。

## 核心功能特性

- **动态模型管理**：基于任务角色动态创建 Ollama 模型，任务结束后自动删除，避免资源占用
- **任务依赖处理**：支持并行任务和依赖任务的串行执行，通过拓扑排序算法控制执行顺序
- **数学计算优化**：生成 Python 代码脚本并执行，确保计算结果的准确性
- **并行任务执行**：使用 ThreadPoolExecutor 实现多执行单元并行处理任务
- **无思考模式**：通过固定 Prompt 强制模型输出结构化结果，避免模型自主决策
- **意图识别**：快速识别用户输入意图，区分简单对话和执行任务
- **直接对话**：对于简单对话，直接生成答复，提高响应速度
- **持续对话**：主对话单元支持持续接收用户输入和交流，不受任务执行影响
- **任务监控**：任务监控单元实时汇报任务进展，用户可随时查询任务状态
- **异步执行**：任务在后台异步执行，不影响主对话单元与用户交流

## 系统架构

### 核心组件

1. **主对话单元**：作为系统的主要交互入口，持续接收用户输入和交流
2. **任务监控单元**：实时汇报任务进展，监控所有执行单元的任务状态
3. **管理控制单元**：负责任务拆解、角色定义、模型分配、执行顺序控制和结果汇总
4. **执行单元**：由管理单元动态创建，每个执行单元绑定一个角色、一个子任务和一个专属 Ollama 模型

### 执行流程

```
用户发送输入 → 主对话单元接收 → 意图识别判断 → 简单对话直接答复 / 执行任务流程 → 任务在后台异步执行 → 任务监控单元实时汇报进展 → 任务完成后汇总结果 → 向用户答复 → 删除执行单元模型
```

## 模型分配方案

| 单元类型       | 选用模型                   | 选用原因                                                                 |
|----------------|----------------------------|--------------------------------------------------------------------------|
| 管理控制单元   | qwen3:1.7b                 | 参数量最大、推理能力最强，能精准拆解复杂任务、定义角色细节、汇总分析多结果 |
| 高级执行单元   | qwen3:4b-instruct          | 大参数量、强推理能力，适配需要深度分析、复杂创作、逻辑推理的高级任务角色 |
| 核心执行单元   | qwen2.5:3b-instruct        | 中等参数量、较强推理能力，适配需要分析/处理能力的核心任务角色             |
| 高级编程单元   | qwen2.5-coder:1.5b          | 专门优化的代码模型，适配需要高质量代码生成、复杂编程任务、算法设计等     |
| 快速编程单元   | qwen2.5-coder:1.5b-instruct-q4_0 | 经过指令微调的4-bit量化版本，适配需要快速代码生成、简单编程任务、脚本编写等 |
| 轻量执行单元   | qwen2.5:1.5b               | 轻量高效，适配简单加工/格式处理类角色                                     |
| 对话执行单元   | qwen3:0.6b                 | 经过指令微调，适配对话沟通、简单问答、咨询等交互式任务                   |
| 极简执行单元   | qwen2.5:0.5b               | 最小参数量、最快推理，适配纯基础执行类角色                               |
| 快速编程单元   | qwen2.5-coder:0.5b         | 最小参数量的代码模型，适配简单代码生成、脚本编写、代码调试等快速编程任务 |

## 环境准备

### 1. 安装依赖

```bash
pip install ollama
```

### 2. 启动 Ollama 服务

确保本地已启动 Ollama 服务：

```bash
ollama serve
```

### 3. 拉取所需模型

```bash
ollama pull qwen3:1.7b
ollama pull qwen3:4b-instruct
ollama pull qwen2.5:3b-instruct
ollama pull qwen2.5-coder:1.5b
ollama pull qwen2.5-coder:1.5b-instruct-q4_0
ollama pull qwen2.5:1.5b
ollama pull qwen3:0.6b
ollama pull qwen2.5:0.5b
ollama pull qwen2.5-coder:0.5b
```

## 使用说明

### 基本交互

- **简单对话**：直接输入问候语、闲聊内容等，系统会立即回复
- **任务执行**：以"请帮我"、"帮我"等关键词开头，系统会启动任务执行流程
- **任务状态查询**：输入"任务"、"状态"、"进度"等关键词，系统会汇报任务进展
- **退出系统**：输入 "exit" 退出系统

### 示例

#### 示例1：简单对话

```
您: 你好
智能体: 您好！我是智能体工作室的对话助手，很高兴为您服务。请问有什么我可以帮助您的吗？
```

#### 示例2：执行任务

```
您: 请帮我计算12345乘以67890的结果
智能体: 我已经让人去处理这个计算任务了，结果出来后会第一时间告诉您。

# 稍后...
智能体: 任务已完成，计算结果为：838102050
```

#### 示例3：查询任务状态

```
您: 任务状态
智能体: 我已经让人去查了，请稍候...

# 详细状态
智能体: 当前任务状态：
- 任务ID: t1
- 角色: 数学计算专家
- 状态: running
- 进度: 正在执行计算任务
- 时间: 2024-01-01 12:00:00
```

## 硬件要求

- **内存**：建议至少 16GB 内存，以支持多个模型同时运行
- **CPU**：建议使用 4 核及以上 CPU
- **存储空间**：至少 50GB 可用空间，用于存储 Ollama 模型

## 注意事项

1. **模型准备**：运行前必须确保所有指定模型已拉取完成
2. **网络连接**：确保网络连接正常，能够访问 Ollama 服务
3. **Prompt 格式**：所有 Prompt 均为固定格式，不可随意修改，否则会导致模型输出解析失败
4. **任务复杂度**：对于复杂任务，建议适当增加子任务拆解的粒度，提高执行效率
5. **错误处理**：系统已实现基本的错误处理，但对于特殊情况可能需要手动干预

## 扩展与优化建议

1. **任务依赖可视化**：添加任务依赖图的可视化功能，便于用户理解任务执行流程
2. **执行单元监控**：实现执行单元的运行状态监控，包括执行时间、内存使用等
3. **模型缓存机制**：对于频繁使用的角色模型，实现缓存机制，避免重复创建
4. **错误重试机制**：添加执行失败的自动重试机制，提高系统稳定性
5. **结果质量评估**：实现执行结果的质量评估，对于质量不达标的结果进行重新执行
6. **多语言支持**：扩展支持多语言任务处理，不仅仅限于中文
7. **用户自定义模型**：允许用户指定自定义模型，增加系统灵活性
